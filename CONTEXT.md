# Контекст проекта

## Продукт

Telegram-платформа, которая соединяет студентов вузов Москвы с исполнителями учебных работ. Клиент выбирает исполнителя из каталога с ценами «от», создаёт заказ, обсуждает условия в сервисе, оплачивает его через платформу и подтверждает приёмку. Платформа удерживает средства до приёмки и выступает гарантом при споре.

## Границы MVP

- Каталог редактируемых категорий учебных работ; формы и правила должны настраиваться без переписывания бизнес-логики.
- Профили исполнителей, цены «от», отзывы и уровни доверия по истории выполненных заказов.
- Университет и курс в профиле; справочники редактируются, отсутствующий вуз можно предложить.
- Создание/ведение заказа, внутренний чат, уведомления Telegram, жалобы, базовая фильтрация контактов и ручная модерация/арбитраж.
- Комиссия удерживается из вознаграждения исполнителя. Оплата резервируется до явного подтверждения клиента или решения арбитра.
- Telegram-бот служит для запуска WebApp и уведомлений; основные действия, в том числе чат с поддержкой, происходят в Mini App.
- Подбор исполнителя оставлен открытым; первый запуск ограничен московскими вузами.

## Технологическая основа

- Python: aiogram 3 для Telegram-интеграции; FastAPI для HTTP API; PostgreSQL как источник истины; SQLAlchemy 2 async и Alembic; Redis для кэша, лимитов и фоновых задач.
- WebApp: React 18 + TypeScript, Vite, `@tma.js/sdk-react`, `@telegram-apps/telegram-ui`.
- Монорепозиторий с модульным монолитом и отдельными процессами API, bot/webhook и worker; Docker Compose для локальной разработки и контейнерный production deploy.

## Ключевые правила

- Доверять только Telegram `initData`, прошедшей серверную проверку подписи и срока давности; `initDataUnsafe` не использовать как удостоверенную личность.
- Деньги отражать внутренним неизменяемым журналом операций; переходы заказа, платежа, возврата и выплаты делать транзакционно и идемпотентно.
- Сообщения и ACL-метаданные чата хранятся в PostgreSQL; сами файлы — в закрытом S3-совместимом Object Storage. В локальной разработке используется MinIO, hosted production storage переключается настройками провайдера (для старта рекомендован Cloudflare R2). Выдавать только короткоживущие подписанные ссылки; ограничивать размер/типы, предусмотреть срок хранения, антивирусную проверку и аудит доступа.
- Не обещать абсолютную блокировку обмена контактами: фильтровать текст, ссылки и вложения, регистрировать жалобы, применять предупреждения/ограничения/баны через модерацию.
- Категории, поля заказов, вузы, курсы, правила комиссии и пороги статусов исполнителя хранить как настраиваемые данные, а не как ветвления по названиям в коде.

## Не решено

- Финальная юридическая схема и российский платёжный провайдер.
- Подбор исполнителя и точные пороги уровней доверия.
- Допустимые форматы помощи для отдельных категорий работ и сроки хранения файлов.
