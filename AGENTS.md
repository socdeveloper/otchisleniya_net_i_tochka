# Правила проекта для Codex

Сначала прочитай краткий [контекст проекта](CONTEXT.md). Открывай ADR только для решений, затронутых задачей; не перечитывай весь контекст в каждом модуле. При изменении доменных правил обновляй соответствующий раздел контекста или ADR.

## Архитектура

Следуй модульному монолиту и доменным границам из `CONTEXT.md` и `docs/adr/`. HTTP- и Telegram-handlers должны оставаться тонкими и вызывать application services. Не связывай домены прямым импортом инфраструктурных репозиториев.

## Skills

Применяй доступные skills автоматически по задаче:

- интерфейсы, границы модулей и масштабирование: `codebase-design`;
- новый функционал и исправления: `tdd`;
- воспроизводимая ошибка или регрессия: `diagnosing-bugs`;
- уточнение терминов/домена и изменение контекста: `domain-modeling`;
- итоговая проверка изменений: `code-review`;
- конфликт при незавершённом merge/rebase: `resolving-merge-conflicts`.

Открывай только SKILL.md выбранного навыка. Не загружай содержание всех skills в контекст заранее.
